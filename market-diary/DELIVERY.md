# 牛牛市场雷达｜Market Diary

> AI 港美股财经情报与内容工作台｜定位：财经内容运营工作台｜富途财经内容运营笔试第二题

## 01｜场景：解决“今天最值得做什么内容”

财经内容运营的难点不是“没有信息”，而是信息过量：公告、财报、政策、媒体、社媒、人物观点和公开持仓持续产生。运营真正需要回答的是：**今天最值得做什么内容、为什么值得做、下一步做成什么。**

因此我没有把AI做成“新闻总结器”，而是把它嵌入完整内容运营工作流：

**获取 → 初筛 → 去重 → AI加工 → Human Check → 内容决策 → 看板沉淀**

最终产品为真实可访问网站 **Market Diary**。首页优先展示3–5条S/A级内容机会，而不是技术指标或全量新闻。

---

## 02｜痛点：传统流程低效在哪里

1. **信息源分散**：官方公告、公司IR、财经媒体、X/小红书、人物发言、持仓披露分散在不同平台。
2. **重复信息很多**：同一事件会被多家媒体重复报道，人工逐篇阅读成本高。
3. **事实与观点混在一起**：社媒热度高不代表事实可靠，财经内容必须回到一级信源。
4. **摘要不等于选题**：知道“发生什么”之后，编辑仍需要判断影响对象、用户价值与内容形式。
5. **经验难复用**：不同编辑对重要性的判断标准不一致，历史内容也容易沉没。

---

## 03｜AI解决方案：机器处理重复劳动，人负责事实和内容判断

### AI负责

- 多源获取与初筛
- 同事件聚类与去重
- 市场 / 类型 / 股票 / 人物标签
- 关键数据提取
- 20–40字一句话结论
- 影响对象与用户价值初步判断
- S / A / B优先级建议
- 快讯 / 解读 / IPO / 社区等内容形式建议
- 关注匹配与素材沉淀

### Human Check负责

- 回到一级信源核对关键事实、数字、日期和口径
- 区分“原文事实”与“AI/市场影响判断”
- 决定是否进入正式发布
- 控制标题和表达边界

**核心原则：AI不是事实来源。AI已处理，不等于可以直接发布。**

网站将Human Check显性展示为：**AI已处理 → 待核验 → 已核验**。

## 05｜信息源：FACT / BUZZ / PEOPLE / MONEY 四层

### FACT｜事实层

SEC、Federal Reserve、BLS、HKEX、公司IR、国家统计局、中国人民银行、中国证监会、香港金管局、香港政府等。

### BUZZ｜热点层

X、小红书。定位是**发现用户在讨论什么**，不是证明事实。社媒信息不能越过Human Check直接成为可发布事实。

### PEOPLE｜人物层

央行官员、政策人物、上市公司管理层、重要投资人及商业人物公开讲话 / 采访 / 官方账号。

### MONEY｜资金层

SEC Form 4、13F、13D/13G、HKEX权益披露等公开披露。其中13F必须明确标注“季度披露、存在时滞，不代表实时仓位”。

### 权威媒体补充

Reuters、Bloomberg、CNBC、FT、WSJ、第一财经、AASTOCKS等用于事件发现与背景补充，关键事实仍优先回到一级信源。

统一原则：**信源权威度解决“能不能信”，内容优先级解决“值不值得做”，两者分开判断。**

## 06｜看板：从信息直接走到内容动作

首页每张S/A级内容机会固定展示：

| 字段 | 回答的问题 |
|---|---|
| 优先级 | 今天先做什么 |
| 一句话结论 | 到底发生了什么 |
| 为什么重要 | 为什么市场 / 用户需要关注 |
| 影响对象 | 股票 / 行业 / 指数 / 用户群 |
| 内容形式 | 快讯 / 解读 / IPO / 社区等 |
| 一级信源 | 事实从哪里来 |
| Human Check | AI处理到哪一步，是否可以进入发布 |

网站包含5页：**今日雷达、事件详情、我的关注、每日精选、内容工作台。**

面试30秒Demo路径固定为：**今日雷达 → 事件详情 → Human Check → 内容工作台**。

## 07｜4条真实样例：原始信息 → AI加工 → Human Check → 内容动作

### 样例1｜NVIDIA Q2 FY2027财报

**原始信息**：NVIDIA IR / SEC 8-K。

关键数据：营收962亿美元、同比+106%；数据中心890亿美元、同比+117%；Non-GAAP EPS 2.22美元。

**AI加工**：同事件聚类 → 数字提取 → 关联NVDA / 半导体 / AI基础设施 / 纳指 → 优先级建议 → 推荐内容形式。

**Human Check**：逐项回到NVIDIA IR / SEC核对财报期、数字和同比口径。

**最终动作**：S级；财报快讯 + 数据卡片 + 财报解读 + 社区讨论。

### 样例2｜阿里巴巴800亿港元配售

**原始信息**：Alibaba Investor Relations / HKEX。

**AI加工**：把拟配售、定价和完成公告聚成同一事件；拆成“短期摊薄”与“AI资本开支加码”两个用户问题。

**Human Check**：核对股数、配售价、募资规模和资金用途，区分公告事实与市场影响判断。

**最终动作**：S级；先做融资事实卡，再解释800亿资金用途及AI战略影响。

### 样例3｜Fed主席Warsh杰克逊霍尔讲话

**原始信息**：Federal Reserve讲话原文。

**AI加工**：从长篇讲话抽取2%目标、PCE数字和政策方向，形成“利率 → 美债/美元 → 成长股估值”的影响链。

**Human Check**：回到Fed原文核对PCE数字和政策措辞，不把市场预期写成官员原话。

**最终动作**：S级；先发核心观点，再做“为什么影响港美科技股”的用户教育。

### 样例4｜SHEIN港股上市安排｜Human Check纠错案例

**原始信息**：HKEX。

**AI加工**：识别IPO事件、关联上市日历，并生成上市前预告和上市后复盘内容方向。

**Human Check发现并纠错**：曾将8月28日的交易安排发布日与上市交易日混淆；回到HKEX核验后，纠正为计划9月1日开始交易。

**最终动作**：A级；上市前新股卡片，上市后切换为首日表现复盘。

这条案例说明：**AI可以大幅处理重复劳动，但财经内容不能牺牲日期、数字和事实口径准确性。**

## 08｜提效：只写真实测试，不虚构数字

本次MVP已实际运行自动工作流。一次实跑中：

- 配置31个数据源 / 路径；
- 21个直接成功；
- 9个直连受限后自动走降级路径；
- 0个硬失败；
- X官方API未配置，因此只使用热点发现回退方案；
- 自动候选经过相关性过滤后从99条收敛到45条，再经编辑排序器进一步收口；
- 脚本改动触发后，约20余秒完成抓取、去重、排序、AI/规则加工并回写网站数据（单次开发环境实测，不等同生产SLA）。

这些技术指标仅用于证明系统真实运行，在网站中下沉到**Source Health / 系统状态**，不作为首页核心价值。

传统人工流程的耗时暂不填写固定数字，因为没有做严格同样本计时测试。真正节省的不是“写30字摘要”的时间，而是减少重复浏览，把编辑时间集中到**Human Check和内容判断**。

## 09｜可复用性：同一信息池服务不同内容节奏

当前系统按小时更新候选池，并支持：

- 港股 / 美股 / 宏观 / IPO / 财报筛选
- 股票 / 人物 / 机构 / 主题关注
- Morning Brief / Evening Brief / Week in Review
- 事件长期沉淀为素材库
- 同一事实复用为快讯、文章、社区、视频选题
- 数据源健康状态和失败降级

最终目标不是“用AI写新闻”，而是建立一套**可重复、可核验、可沉淀的财经内容运营工作流**。

## 当前边界（主动说明）

1. **X官方Recent Search**：代码已预留，但未配置API Token；当前X仅用于公开热点发现，不宣称真实全量热度。
2. **小红书**：V1只保留半自动 / 合规数据源接口，不做违规全站抓取。
3. **SEC自动抓取**：GitHub Actions出口访问SEC会出现HTTP 403，因此V1明确显示“源受限”，不伪造自动持仓数据；正式环境需使用符合SEC Fair Access要求的采集环境或合规数据服务。
4. **HKEX持股批量数据**：需遵守HKEX数据许可，V1不绕过授权抓取付费数据。

这些边界不会阻断主流程：系统会展示源健康状态，单一来源异常不会被静默忽略，也不会被包装成正常数据。
