# 牛牛市场雷达｜Market Diary

> AI 港美股财经情报与内容工作台｜富途财经内容运营笔试第二题

## 01｜场景：为什么做「港美股每日内容雷达」

财经内容运营的难点不是“没有信息”，而是信息过量：公告、财报、政策、媒体、社媒、人物观点和公开持仓每天持续产生。运营真正需要解决的是：**今天什么值得做、为什么值得做、下一步做成什么内容。**

因此我没有把AI做成“新闻总结器”，而是把它嵌入完整内容工作流：

**获取 → 初筛 → 去重 → 核验 → 结构化 → 评分 → 内容化 → 看板沉淀**

最终产品为真实可访问网站 **Market Diary**，同时保留未来作为个人财经内容源继续使用的能力。

---

## 02｜痛点：传统流程低效在哪里

1. **信息源分散**：官方公告、公司IR、财经媒体、X/小红书、人物发言、持仓披露分散在不同平台。
2. **重复信息很多**：同一事件会被多家媒体重复报道，人工逐篇阅读成本高。
3. **事实与观点混在一起**：社媒热度高不代表事实可靠，财经内容需要严格回到一级信源。
4. **摘要不等于选题**：知道“发生什么”之后，编辑仍需要判断影响对象、用户价值与内容形式。
5. **经验难复用**：不同编辑对重要性的判断标准不一致，历史内容也容易沉没。

---

## 03｜AI解决方案：机器做高频工作，人做高价值判断

### 机器负责

- 多源抓取
- 初步去重
- 市场 / 类型 / 股票 / 人物标签
- 关键数据抽取
- 20–40字结论
- 影响对象识别
- S / A / B初步评分
- 推荐快讯 / 解读 / IPO / 社区等内容形态
- 素材沉淀与关注匹配

### 人负责

- 关键事实与数字核验
- 信息是否真正影响用户
- 是否值得发布
- 标题和表达边界
- 最终内容判断

**核心原则：AI不是事实来源。**

---

## 04｜工具链：轻量、可替换、可以长期运行

| 环节 | 当前实现 | 作用 |
|---|---|---|
| 数据采集 | Node.js + RSS / 官方域名发现 / 官方接口预留 | 自动获取候选信息 |
| 定时任务 | GitHub Actions | 每小时自动运行 |
| AI加工 | OpenAI-compatible接口 + 规则回退 | 摘要、结构化、评分、内容建议 |
| 人工核验 | SEC / Fed / HKEX / 公司IR / 政府原文 | 关键事实最终确认 |
| 前端 | HTML / CSS / JavaScript | 5个真实可操作页面 |
| 数据沉淀 | JSON结构化数据 | 看板、关注、每日精选复用 |

AI模型不是硬绑定：可通过环境变量替换模型服务；未配置AI密钥时，系统自动使用规则模型，不让整条链路中断。

## 05｜信息源：事实、热点、人物、资金四层

### FACT｜事实层

SEC、Federal Reserve、BLS、HKEX、公司IR、国家统计局、中国人民银行、中国证监会、香港金管局、香港政府等。

### BUZZ｜热点层

X、小红书。

定位是**发现用户在讨论什么**，不是证明事实。社媒信息默认不能越过一级信源核验环节。

### PEOPLE｜人物层

央行官员、政策人物、上市公司管理层、重要投资人及商业人物公开讲话 / 采访 / 官方账号。

### MONEY｜资金层

SEC Form 4、13F、13D/13G、HKEX权益披露等公开披露。

其中13F必须明确标注“季度披露、存在时滞，不代表实时仓位”。HKEX DI / CCASS 等批量数据在自动化前先确认数据许可，不绕过授权。

### 内容补充源

Reuters、Bloomberg、CNBC、FT、WSJ、第一财经、AASTOCKS等用于事件发现与背景补充，最终关键事实仍优先回到一级信源。

## 06｜看板：不是纯新闻摘要，而是编辑操作台

核心字段：

| 字段 | 回答的问题 |
|---|---|
| 时间 / 市场 / 类型 | 什么时候、哪个市场、什么事件 |
| 事件 / 一句话结论 | 到底发生了什么 |
| 核心数据 | 最重要的数字是什么 |
| 为什么重要 | 为什么市场 / 用户需要关注 |
| 影响对象 | 股票 / 行业 / 指数 / 用户群 |
| 用户价值 | 用户看完能解决什么问题 |
| 信源 / 可信度 | 事实从哪里来、能不能信 |
| 热度 | 市场 / 社媒是否正在讨论 |
| 优先级 | S今天必须做 / A值得做 / B素材库 |
| 建议动作 | 运营下一步具体干什么 |
| 内容方向 | 快讯 / 解读 / 深度 / IPO / 社区 |
| AI辅助方式 | AI在这条信息里具体做了什么 |

网站包含5页：**今日雷达、事件详情、我的关注、每日精选、内容工作台。**

## 07｜4条真实样例：原始信息 → AI加工 → 最终看板

### 样例1｜NVIDIA Q2 FY2027财报

**原始信息**：NVIDIA IR / SEC 8-K。

关键数据：营收962亿美元、同比+106%；数据中心890亿美元、同比+117%；Non-GAAP EPS 2.22美元。

**AI加工**：同事件聚类 → 数字抽取 → 关联NVDA / 半导体 / AI基础设施 / 纳指 → 评分 → 推荐内容形态。

**Human Check**：逐项回到NVIDIA IR / SEC核对财报期、数字和同比口径。

**最终动作**：S级；财报快讯 + 数据卡片 + 财报解读 + 社区讨论。

### 样例2｜阿里巴巴800亿港元配售

**原始信息**：Alibaba Investor Relations / HKEX。

**AI加工**：把拟配售、定价和完成公告聚成同一事件；拆成“短期摊薄”与“AI资本开支加码”两个用户问题。

**最终动作**：S级；先做融资事实卡，再解释800亿资金用途及AI战略影响。

### 样例3｜Fed主席Warsh杰克逊霍尔讲话

**原始信息**：Federal Reserve讲话原文。

**AI加工**：从长篇讲话抽取2%目标、PCE数字和政策方向，形成“利率 → 美债/美元 → 成长股估值”的影响链。

**最终动作**：S级；先发核心观点，再做“为什么影响港美科技股”的用户教育。

### 样例4｜SHEIN港股上市安排

**原始信息**：HKEX。

**AI加工**：识别IPO事件、关联上市日历，并把“公告日”和“实际交易日”分开。

**Human Check发现并纠错**：8月28日是交易安排发布日，实际计划交易日为9月1日。

**最终动作**：A级；上市前新股卡片，上市后自动切换为首日表现复盘。

这一条也体现了为什么财经AI必须有Human Check：**模型可以提效，但不能牺牲日期和数字准确性。**

## 08｜提效：只写真实测试，不虚构数字

本次真实MVP已运行自动工作流。

一次实跑中：

- 配置31个数据源 / 路径；
- 21个直接成功；
- 9个直连受限后自动走降级路径；
- 0个硬失败；
- X官方API未配置，因此只使用热点发现回退方案；
- 自动候选经过相关性过滤后从99条收敛到45条，再经编辑排序器收敛为少量A级事件与B级素材；
- 脚本改动触发后，约20余秒完成抓取、去重、排序、AI/规则加工并回写网站数据（单次开发环境实测，不等同生产SLA）。

传统人工流程的耗时暂不填写固定数字，因为本次没有做严格同样本计时测试。正式对比时应使用同一批信息分别进行人工处理和AI辅助处理，再记录：阅读文章数、去重耗时、核验耗时、最终选题数。

**真正节省的不是“写30字摘要”的时间，而是把编辑从大量重复浏览中释放出来，把时间集中到核验和判断。**

## 09｜可复用性：第二天不需要重做一遍

系统按小时更新候选池，并支持：

- 港股 / 美股 / 宏观 / IPO / 财报筛选
- 股票 / 人物 / 行业 / 主题关注
- 自动生成每日精选
- 事件长期沉淀为素材库
- 同一事实复用为快讯、文章、社区、视频选题
- 数据源失败状态监控和降级
- 模型可替换
- 后续可增加Morning Brief / Evening Brief / Week in Review

最终目标不是“用AI写新闻”，而是建立一套**可重复、可核验、可沉淀的财经内容运营系统**。

## 当前边界（主动说明）

1. **X官方Recent Search**：代码已预留，但未配置API Token；当前X仅用于公开热点发现，不宣称真实全量热度。
2. **小红书**：未发现适合该场景的官方全站公开搜索API，因此V1只保留半自动 / 合规数据源接口，不做违规全站抓取。
3. **SEC自动抓取**：GitHub Actions出口访问SEC会出现HTTP 403，因此V1将SEC标为“源连接受限”，不伪造自动数据；正式部署时应使用符合SEC Fair Access要求的独立采集环境或合规数据服务，并继续保留SEC原文作为最终事实依据。
4. **HKEX持股批量数据**：需遵守HKEX数据许可，V1不绕过授权抓取付费数据。

这些边界不会阻断主流程：系统会展示源健康状态，并在某一数据源不可用时让其他来源继续运行，避免“一个源挂掉，整条链路失效”。
