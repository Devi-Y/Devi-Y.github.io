# 牛牛市场雷达｜Market Diary

一个面向港美股财经内容运营的轻量工作台：先判断最近最值得看什么，再追问、比较，并把已核验事件转成可直接使用的速览、深读或对比。

> 发布说明（2026-09-03）：本轮 P0 已通过代码、数据契约和多尺寸浏览器验收；此文档随 `main` 发布，线上状态以 GitHub Pages 当前部署为准。

## 核心闭环

**先看重点 → 看懂影响 → 核验证据 → 横向对照 → 生成内容 → 持续关注**

产品保持三条明确边界：

- AI/规则负责聚合、去重、结构化和内容建议，不作为事实来源。
- `data/events.json` 是已核验内容层；自动候选不会进入首页已核验主线或重点，只在明确标注的候选区展示。
- `data/candidates.json` / `data/ai-candidates.json` 是待核验线索层，只能生成核验清单。

## 四个入口

1. **今日**：先看一条主线，再看当前三条已核验重点；不会把旧事件或未来日历冒充“今天发生”。
2. **问一下**：用自然语言找事件，并按速览、深读、对比三种格式生成结构化内容。
3. **市场**：提供事件总览、下一节点、任务入口、事件检索与同口径对照；当前明确不是实时行情页。
4. **我的**：本机保存关注、草稿，并区分数据集更新时间、候选加工方式和来源运行状态。

当前稳定路由为 `#radar`、`#workbench`、`#market`、`#my` 和可分享的 `#event/<id>`。旧链接仍兼容：`#daily` 映射到“今日”，`#library` / `#content` 映射到“市场”的事件列表，`#watchlist` 映射到“我的”；`#detail` 不作为稳定分享链接。

## 证据与隐私

- 每份可生成内容固定展示关键事实、编辑判断、风险边界、一级/辅助信源和下一步。
- 待核验候选不生成可发布成稿。
- 事件比较只对照市场、类型、日期、来源、证据状态和编辑动作；自由文本关键数字不参与大小比较或排名。
- “影响对象”和“为什么重要”明确标为编辑判断，不冒充原始信源结论。
- 关注与草稿只写入当前浏览器的 `localStorage`。
- 匿名使用统计默认关闭；只有访客明确允许后，才创建随机浏览器编号并发送页面与白名单动作。
- 统计不发送提问、搜索词、关注、草稿、剪贴板、完整网址、完整 User-Agent 或精确位置，也不把 IP 写入分析记录；Vercel 作为托管商在提供网络请求时可能短暂处理连接信息。记录最多保留 90 天，访客可随时停止并重置编号。
- 若站长需要区分受邀对象，后台会生成无含义的随机邀请码，并把邀请码映射到备注；姓名或备注不会出现在分享网址中，访客同意后才会归因。

## 匿名使用分析

分析后端位于独立的 `market-diary-insights` Vercel 项目，与问岳、望潮等项目的数据和密钥隔离。前台按会话批量发送，避免一次点击写一次存储；管理员看板支持 7 / 30 / 90 天、匿名访客与会话、按钮排行、页面热度、关键漏斗、专属邀请链接、最近行为和 CSV 导出。

“访客人数”只代表已同意统计的匿名浏览器编号，不等于全部真实人数：拒绝统计者不会进入数据，清理浏览器、换浏览器或换设备也会生成新编号。

详细比较门槛与后续结构化字段见 [`DATA_CONTRACT.md`](./DATA_CONTRACT.md)。

## 自动化

GitHub Actions 每小时更新候选池、AI/规则加工结果、来源健康和 SEC 观察数据。候选更新与人工核验内容更新时间在 UI 中分开显示。

主要脚本：

- `scripts/update-candidates.mjs`：多源采集、时间窗、降级和初步去重。
- `scripts/rank-candidates.mjs`：按影响、时效和内容价值排序。
- `scripts/collect-sec-watchlist.mjs`：公开披露观察。
- `scripts/enrich-candidates.mjs`：AI 加工；无密钥时使用规则回退。
- `scripts/test-frontend.mjs`：前端结构、隐私边界和数据契约检查。

## 本地运行与检查

```bash
python3 -m http.server 4173 --directory .
node --check market-diary/app.js
node --check market-diary/sw.js
node market-diary/scripts/test-frontend.mjs
cd market-diary-insights && npm test
```

打开 `http://127.0.0.1:4173/market-diary/#radar`。

## 当前技术边界

GitHub Pages 不能安全保存模型密钥，因此自然语言匹配与成稿输出只使用已经进入站点的结构化数据。当前自动候选会如实显示模型是否配置；规则回退不会包装成模型分析。若未来需要开放式实时问答，必须增加受控后端代理，不能把 API Key 放到浏览器。
